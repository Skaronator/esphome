# ESPHome notes: XIAO ePaper Display Board EE02 + 13.3" 6‑color T133A01 (BOARD_SCREEN_COMBO 510)

This note consolidates the hardware/driver details from the Seeed_GFX/TFT_eSPI configuration for:

- `BOARD_SCREEN_COMBO 510` (13.3 inch six‑color ePaper Screen, T133A01)
- `USE_XIAO_EPAPER_DISPLAY_BOARD_EE02`

Use this as a reference when implementing the display in ESPHome (custom component or external driver).

---

## 1) Display parameters (from setup)

From [User_Setups/Setup510_Seeed_XIAO_EPaper_13inch3_colorful.h](User_Setups/Setup510_Seeed_XIAO_EPaper_13inch3_colorful.h):

- Driver: **T133A01** (`#define T133A01_DRIVER`)
- E‑paper enabled: `EPAPER_ENABLE`
- Resolution: **1200 x 1600**
  - `TFT_WIDTH 1200`
  - `TFT_HEIGHT 1600`
  - `EPD_WIDTH TFT_WIDTH`, `EPD_HEIGHT TFT_HEIGHT`
- Color depth: **4 bpp** (6‑color) from [TFT_Drivers/T133A01_Defines.h](TFT_Drivers/T133A01_Defines.h):
  - `EPD_COLOR_DEPTH 4`
  - `USE_COLORFULL_EPAPER`

> Note: T133A01 define file defaults to 1600x1200 if EPD/TFT sizes are not set, but Setup510 overrides to 1200x1600. Keep the 1200x1600 orientation for this board.

## 2) Pin mapping for XIAO ePaper Display Board EE02

From [User_Setups/EPaper_Board_Pins_Setups.h](User_Setups/EPaper_Board_Pins_Setups.h):

```text
USE_XIAO_EPAPER_DISPLAY_BOARD_EE02

TFT_SCLK   D8
TFT_MISO   -1
TFT_MOSI   D10
TFT_CS     44   // D7
TFT_CS1    41   // D8 (second chip select)
TFT_DC     10   // D16
TFT_BUSY   4    // D3
TFT_RST    38   // D11
TFT_ENABLE 43
```

### Notes

- **Two chip‑selects** are used: `TFT_CS` and `TFT_CS1`.
- `TFT_MISO = -1` (No MISO line).
- `TFT_ENABLE` is present and should be driven high to power/enable the display.
- Busy pin is required by the driver’s polling logic (`CHECK_BUSY`).

## 3) SPI and bus behavior

From [TFT_Drivers/T133A01_Defines.h](TFT_Drivers/T133A01_Defines.h):

- Driver uses SPI with explicit command/data phases.
- Busy‑wait macro (polls `TFT_BUSY` and delays 10ms per iteration).
- Uses **dual‑CS** semantics in multiple sequences:
  - Some commands go through `TFT_CS1` (power and control path)
  - Pixel data is sent through `TFT_CS`
- Requires a reset pulse sequence:
  - `TFT_RST` low → delay 20ms → high → delay 20ms

ESPHome implementation must therefore:

1. Configure **two CS lines** (or a custom SPI bus abstraction that can toggle each CS).
2. Support **command vs data** operations (`DC` pin).
3. Poll `BUSY` between critical operations.
4. Expose `ENABLE` pin (drive high during init and runtime).

## 4) Init / update / sleep sequences (T133A01)

From [TFT_Drivers/T133A01_Defines.h](TFT_Drivers/T133A01_Defines.h):

### Initialization (`EPD_INIT`)

Key operations (abridged):

- Reset pulse (see above)
- `CHECK_BUSY`
- Write multiple registers and LUT/config tables:
  - `0x74`, `0xF0`, `R00_PSR`, `R50_CDI`, `0x60`, `0x86`, `RE3_PWS`, `R61_TRES`, `R01_PWR`, `0xB6`, `R06_BTST_P`, `0xB7`, `R05_BTST_N`, `0xB0`, `0xB1`
- Many operations are sent with `TFT_CS1` toggling, while some are sent without changing CS (see file for precise sequence).

### Update (`EPD_UPDATE`)

- `TFT_CS1` low → `R04_PON` (power on) → wait busy
- `R12_DRF` (display refresh) → wait busy
- `R02_POF` (power off) → wait busy

### Sleep (`EPD_SLEEP`)

- Write `0x07` with `0xA5` then wait busy

## 5) Pixel format and color mapping

From [TFT_Drivers/T133A01_Defines.h](TFT_Drivers/T133A01_Defines.h):

- Incoming pixel buffer is **4‑bit per pixel**, two pixels packed per byte.
- `COLOR_GET` remaps logical 4‑bit colors to device palette indices:

```text
COLOR_GET(color) =
  0x0F -> 0x00
  0x00 -> 0x01
  0x02 -> 0x06
  0x0B -> 0x02
  0x0D -> 0x05
  0x06 -> 0x03
  else -> 0x01
```

- Two‑plane write: `EPD_PUSH_NEW_COLORS` writes two passes over the buffer:
  - Pass 1 sends the **upper** nibble mapped to color (per byte)
  - Pass 2 sends the **lower** nibble mapped to color (per byte)

This is not a standard RGB order; it is a palette‑mapped 6‑color ePaper flow. Any ESPHome renderer must either:

- output packed 4‑bit palette indices per the mapping above, or
- convert from RGB to this palette and pack bytes, then send with the two‑pass method.

## 6) Practical implications for ESPHome

### Required pins

- CS pin (`TFT_CS`)
- Second CS pin (`TFT_CS1`), not standard in ESPHome
- DC pin
- Reset pin
- Busy pin
- Enable pin
- Clock pin and MOSI pin (no MISO pin)

### Data flow

- **Command/data split** and **busy polling** are mandatory for stability.
- **Dual‑CS** control is mandatory; stock ESPHome SPI display platforms typically support only one CS. Expect to implement a custom component or extend the driver.

### Resolution / buffer size

- 1200×1600 @ 4 bpp → framebuffer size ≈ $1200 \times 1600 / 2 = 960{,}000$ bytes (~938 KB)
- Use **PSRAM** and partial buffering if possible.
